# Artifact Storage Policy

This document records what derived artifacts exist, where they live, what is
allowed in git, and where large raw datasets should be stored instead.

## What the build produces

| Artifact | Path | Tracked in git? | Notes |
| --- | --- | --- | --- |
| Rendered site | `dist/cantilever/` | No (`dist/` ignored) | Deployed by Cloudflare Pages |
| Publish bundle (site, `llms.txt`, context, RAG, IR) | `publish/` | No (`publish/` ignored) | Produced by `scripts/ted-publish.sh` |
| Local preview output | `dist/preview/` (or `DIST_DIR`) | No | `./preview.sh` |
| Boris compiler binary + manifest | `bin/boris`, `bin/boris.json` | No (`bin/boris*` ignored) | Built by CI from the Boris source and placed in `bin/`; binary is ~9 MiB |
| Zig toolchain + caches | `.tools/` | No (`.tools/` ignored) | Compiler downloads and build cache |
| Identity migration map | `metadata/id-map.jsonl` | **Yes — deliberately** | Generated by `scripts/ted_ids.py --write`; it is the migration record (see `metadata/id-policy.json`) |

## Rules

1. Generated build output is **never** committed (`dist/`, `publish/`,
   `site/`, `exports/`, `.tools/`, `bin/boris*`). The audit
   (`scripts/audit_public_release.py`) fails on any of these appearing in
   git.
2. `metadata/id-map.jsonl` is the single intentional exception — it is
   generated, tracked, and marked `linguist-generated` in `.gitattributes`.
3. Local raw datasets (unprocessed lab certificates, scans, spreadsheets)
   are **not** committed anywhere; see "External storage" below.

## External storage for large raw datasets

The repository is for **source content**, not bulk data. If a future dataset
(COA archives, terpene measurement corpora, image sets) is larger than a few
megabytes or is not text, store it externally and reference it:

| Option | Best for | Notes |
| --- | --- | --- |
| Cloudflare R2 (private bucket) | raw lab artifacts, large archives | Same provider as the site; keep the bucket private |
| GitHub Releases | versioned snapshots bundled with releases | Public by default — only for category-1 data (`PRIVACY.md`) |
| Zenodo / institutional archive | citable research datasets | Adds DOI + long-term preservation |
| S3-compatible object storage | bulk machine data | Prefer versioned buckets with lifecycle rules |

Every external dataset must carry a manifest (file list + SHA-256 hashes +
provenance fields) that is committed in this repository, so downstream
processes can verify integrity. Never point the site at a private bucket;
publish only derived, category-1/2 data as static files.

## Verification

* `scripts/audit_large_files.py` lists giant tracked files, reachable
  history blobs, and external-storage candidates.
* Before public release, confirm no blob above the threshold
  (default 5 MiB) is reachable in history.
