## Scope

Michigan Cannabis Regulatory Agency (CRA) rules, testing guidance, recalls,
enforcement notices, laboratory identities, and aggregate reports. Michigan is
the project's third deeply implemented jurisdiction after California and
Massachusetts, and the first whose primary sources are documents rather than
bulk datasets.

## Implementation state

- Adapter: **none**. There is no `scripts/ingest/states/michigan.py`, and
  `scripts/state_ingest.py` accepts `massachusetts` only. This is a deliberate
  decision, not an omission — see "Why there is no adapter" below.
- Canonical command: none. Michigan artifacts are compact reviewable JSON
  assembled from source-specific evidence, not generated by a live pipeline.
- Generated content: 28 Michigan content files across the shared canonical
  collections — `jurisdictions/TJUR-0023`, `licenses/TLIC-0031..0033`,
  `organizations/TORG-0063..0068`, `testing-laboratories/TSTL-0029..0031`,

- ID allocation: Michigan replaced the earlier stub in place and kept

- Durable artifacts: `data/michigan-cra/` tracks five files —
  `licenses.json`, `laboratories.json`, `recalls.json`, `manifest.json`, and

  source rows. No raw HTML, PDF, or DOCX source is committed.
- Fixtures and tests: **none**. There is no `tests/test_michigan.py`, because
  there is no adapter to test. Michigan content is covered only by the
  repo-wide graph, ID, crosslink, and content audits.

## Why there is no adapter

Recorded in `reports/michigan-jurisdiction-friction.md` and
`reports/michigan-jurisdiction-wave.md`, both dated 2026-08-09:

- CRA license verification is an interactive Accela search, and the periodic
  licensing reports are DOC/DOCX aggregates. There is no bulk row source to
  fetch or diff.
- The Massachusetts adapter assumes a stable CSV/JSON catalog. Retrofitting it
  for HTML/PDF/DOCX scraping would create a second ingestion architecture and
  hide the source friction rather than record it.
- The wave deliberately did not add an Accela or Metrc crawler, a guessed bulk
  registry API, or synthetic Michigan COA records.

The recorded architectural conclusion is that the next shared improvement
should be a documented document-source adapter contract, not a Michigan-specific
crawler.

## Open items

- No state lane automation: Michigan cannot be re-synced or diffed, so its
  evidence ages silently. There is no staleness guard equivalent to the
  Massachusetts stale-source regression test.
- `content/recalls` is not jurisdiction-neutral: California uses `recalls` and
  Massachusetts uses `safety-advisories`, while Michigan uses both recall and
  consumer-advisory terminology. Michigan records currently sit in `recalls`
  with the event type preserved in the record.
- CRA labels its guidance link v5.1 on one page surface while the fetched PDF
  is v5.2 revised 2024-09-23. The manifest records the PDF version and
  `TREQ-0003` carries the caveat; the discrepancy is upstream.
- Laboratory entity resolution is incomplete: current CRA status, full licence
  history, accreditation scope, and parent-company relationships are unresolved
  for PSI, ACT, and Reassure unless the source states them.
